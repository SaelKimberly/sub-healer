Problem

run_with_config() threads real HTTP client, real SQLite, real Telegram through entire pipeline. Only testable by hitting network + filesystem. Pipeline glue was 0% tested.

Implementation

Seam via generics: ConfigSource trait + YamlConfigSource, SourceFetcher trait + LiveFetcher, Pipeline<C, F>. DB passed as &rusqlite::Connection — :memory: SQLite for tests (no DbAdapter trait needed). run_with_config wraps Pipeline::new(YamlConfigSource, LiveFetcher).run(client, conn).

Wins

  • 4 pipeline tests (empty sources, registry upsert, config upsert, multiple configs)
  • Pipeline testable without network/filesystem
  • Enables #3 (config struct) as next step

Problem

impl ProtoSpec for ProtocolConfig dispatched 12 trait methods across 11 variants = 132 arms of pure delegation.

Implementation

#[enum_dispatch] panicked on static method try_parse — enum_dispatch doesn't support static methods. Replaced with dispatch! macro generating 11-arm match for each of 10 instance methods. try_parse stays as an inherent-style trait method. enum_dispatch dependency removed from Cargo.toml.

5 pre-existing test failures (SSR InvalidStructure, SlipnetEnc InvalidUserInfo, WireGuard stub, etc.) also resolved.

Wins

  • Delegation centralized in one macro — adding protocol = one variant + one config file
  • No external dependency for dispatch
  • TryParse stays generic for check_roundtrip<T: ProtoSpec>
